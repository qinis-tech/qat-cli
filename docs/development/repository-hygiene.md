# Repository Hygiene

Two policies live here. They are independent on purpose.

|               | Policy A — Git              | Policy B — npm                    |
| ------------- | --------------------------- | --------------------------------- |
| Question      | What do we **keep**?        | What do we **give away**?         |
| Configured in | `.gitignore`                | `package.json` → `files`          |
| Default       | Everything, unless excluded | Nothing, unless included          |
| Audience      | Contributors                | Everyone who installs the package |

A change to one is never a change to the other. Reviewing a diff that touches both
should make you suspicious: they answer different questions.

---

# Policy A — Git exclusion

Default is **include**. An entry here is a claim that a file can be rebuilt, or that it
must never be shared.

## Excluded categories

| Category          | Patterns                                                    | Why                                                                        |
| ----------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------- |
| Dependencies      | `node_modules/`                                             | Restored by `npm ci` from the committed lockfile                           |
| Build output      | `dist/`, `*.tsbuildinfo`                                    | Emitted by `tsc`; regenerating it is the build                             |
| Coverage          | `coverage/`, `reports/`, `junit.xml`                        | Generated by the test run                                                  |
| Runtime artefacts | `.qat/`                                                     | Results, screenshots, video, local history DB. May capture production data |
| Local databases   | `*.db`, `*.sqlite`, `*.sqlite3`, `-wal`, `-shm`, `-journal` | Local evidence, never a source of truth                                    |
| Environment files | `.env`, `.env.*`, except `*.example`                        | Configuration for one machine                                              |
| Key material      | `*.pem`, `*.key`, `*.p12`, `*.pfx`, `*.jks`, `*.keystore`   | Keys belong in a secret store, never a working tree                        |
| Temporary         | `*.log`, `*.tmp`, `*.bak`, `.cache/`                        | Regenerable, or meaningless                                                |
| Editor/IDE        | `.vscode/*` (except two files), `.idea/`, `*.swp`           | Machine-specific noise                                                     |
| OS metadata       | `.DS_Store`, `Thumbs.db`, `desktop.ini`                     | Not project content                                                        |

## Intentionally committed

`package-lock.json` · `.npmrc` (never containing a token) · `.github/` · `docs/` ·
`.vscode/extensions.json` · `.vscode/settings.json`

## The one rule that catches everyone

Git cannot re-include a file from a directory it has been told to ignore **entirely**.

```gitignore
.vscode/*                    # correct — the directory is traversable
!.vscode/extensions.json     # so this works

.vscode/                     # wrong — the directory is opaque
!.vscode/extensions.json     # so this does nothing, silently
```

No warning is produced. If a negation appears not to work, check the parent pattern
before anything else.

# Policy B — npm publication

Default is **exclude**. `files` in `package.json` is an allowlist.

```jsonc
"files": ["dist", "CHANGELOG.md"]
```

Anything not listed is excluded, including files nobody has considered yet. That
inversion is the point: an exclusion list can only name dangers someone remembered.

## Included

| Path                   | Why                                                                                          |
| ---------------------- | -------------------------------------------------------------------------------------------- |
| `dist/**`              | Compiled output. Includes `dist/ci/templates/**`, carried there by `scripts/copy-assets.mjs` |
| `CHANGELOG.md`         | Release history users read before upgrading                                                  |
| `package.json`         | Mandatory; npm includes it regardless                                                        |
| `README.md`, `LICENSE` | Mandatory; npm includes them regardless                                                      |
| The `bin` target       | Mandatory; npm includes it regardless                                                        |

## Excluded

`src/` · `tests/` · `tests/fixtures/` · `coverage/` · `.qat/` · `*.db` · `.env*` ·
`.github/` · `scripts/` · most of `docs/` · `.git*` · any key material

## No `.npmignore`

Do not create one. When `files` is present npm ignores `.npmignore` entirely, so the two
would appear to govern one decision while only one does. Adding `.npmignore` later would
change nothing — which is worse than it failing, because it would look like it worked.

## Source maps

The build emits `.js.map` with `inlineSources: true`, so a stack trace a user reports
resolves to readable code without shipping `src/`. Without `inlineSources`, maps point at
paths that are not in the package and every reported stack trace is unreadable.
`declarationMap` is off: there is no `types` entry, so nothing consumes it.

# Secret protection

Four independent layers. Each one assumes the others may fail.

| Layer                                     | Catches                                                                     |
| ----------------------------------------- | --------------------------------------------------------------------------- |
| `.gitignore` patterns                     | The obvious file types, before `git add`                                    |
| Publication allowlist                     | Anything unlisted, including a committed secret — it cannot ship            |
| `scripts/verify-package.mjs` content scan | Private key blocks, cloud access keys, npm and GitHub tokens in packed text |
| GitHub push protection + secret scanning  | Credentials recognised by the hosting provider, including in history        |

Rules:

1. **No credential is ever committed**, including for local development, including in a
   branch nobody will merge. History is not erasable once pushed.
2. **Publish credentials live in `~/.npmrc`**, outside the repository. A repository
   `.npmrc` configures registry and access only.
3. **`.env.example` documents variable names, never values.** It is the only `.env` file
   in the repository.
4. **Fixtures are synthetic.** No real hostnames, tokens, customer data, or screenshots of
   production systems. This applies to recorded video too.
5. **If a credential is committed, treat it as compromised.** Rotate it first; cleaning
   history is the second step, not the first.

# Verification

```bash
npm run build          # required — the check inspects real output
npm run verify:package # exits non-zero if the inventory violates policy
```

`npm pack --dry-run` remains useful for a human reading the list:

```bash
npm pack --dry-run
```

The script wraps that and adds assertions, so the policy is enforced on the release that
matters rather than reviewed once. Run it in CI and in the release workflow **before**
`npm publish`.

## Expected inventory

Roughly 10 files: `package.json`, `README.md`, `LICENSE`, `CHANGELOG.md`,
`dist/cli/index.js` plus source map, `dist/shared/**` plus maps,
`dist/ci/templates/github-actions/*.yml`.

If the count grows substantially, something entered `dist/` that the build did not intend.

## When the check fails

| Message                            | Cause                                            | Fix                                                                   |
| ---------------------------------- | ------------------------------------------------ | --------------------------------------------------------------------- |
| `not on the publication allowlist` | A new file enters `dist/` via the build          | Confirm it belongs in the product, then extend `ALLOWED` deliberately |
| `missing required file`            | `dist/` not built, or the asset copy did not run | `npm run build`; check `scripts/copy-assets.mjs`                      |
| `forbidden path …`                 | Something shipped that policy excludes           | Find what put it there — usually a missing build exclusion            |
| `… : private key block`            | A key reached a packed file                      | Rotate the key. Then remove it and add a guard                        |

Fix the cause. Widening the allowlist to silence a failure is how an allowlist becomes an
exclusion list.
